# 按目标、资源与预算选择落地途径

在形成方案/落地建议时读。回答“这想法适合用户怎样做出来并持续使用”，不默认每个idea都应成为开源仓或收费产品。建议由当前需求和证据支撑，预算多少不直接决定路线。

## 1. 最小资源画像

先复用requirements与已知资料，不重复访谈。只追问会改变路线的重大意图或投入边界；现有能力、工具和成本事实由agent查。

- **目标**：自用、科研、作品/学习、社区贡献、收入或机构落地；多目标有先后。是否愿意公开、服务用户、长期维护。
- **时间与能力**：可持续投入、期限，开发/领域/产品能力，现有agent能辅助的部分，以及仍需本人或合作方承担的维护。
- **现金边界**：用户愿投入的首期上限、持续支出上限、可接受损失；与agent的工作量/费用估计分开。未给预算写未知，明确零新增预算才按零考虑，不从个人存款或借款能力推断愿投资金。
- **现有资源**：代码/工具、设备/算力、可用数据与访问权、团队/合作、首批使用者和触达渠道。缺失写未知，不能假设有免费劳动力、现成客户或无限维护时间。

资金、时间、技能、数据或渠道的缺口可能互相替代，也可能构成硬约束；不能用有钱替代需求证据，或用agent会编码替代交付与维护能力。无关项标不适用，不为简单自用任务做完整创业问卷。

## 2. 分开两种选择

**实现来源**：现成工具/配置 → 开源二开 → 必要的自建 → 合作或外包，按实际能力与缺口比较。

**交付/运营途径**：私下自用、科研/作品原型、公开开源、交付服务/定制合作、可重复收费产品、接入/授权既有产品等。开源代码可以自用或商业化；收费也可以基于开源核心。两者不是互斥选项，不能把“开源”自动写成“全部公开、零成本、不收费”。

允许分阶段：先解决自己问题/验证方法，再选择公开、服务或产品化。每次升级应有新证据、资源和授权，不因做了原型就自动升级成平台。

## 3. 按适配条件比较，不按固定金额划档

| 途径 | 值得考虑的条件 | 起步与关键验证 | 持续负担/转向条件 |
|---|---|---|---|
| 现成工具直接自用/配置 | 自己的问题明确，现成能力足够，时间或维护资源有限 | 完成一个真实任务，验证缺口和实际使用成本 | 订阅/配置维护；只有具体缺口值得补时才二开 |
| 二开或小型内部工具 | 有明确差异需求，可复用现有代码，具备或能获得维护能力 | 只打通一个使用闭环，检查输入输出和升级依赖 | 跟随上游、环境与数据维护；补缺收益不足则回现成方案 |
| 科研/学习/作品原型 | 目标是验证假设、方法或展示能力，尚不承诺生产运营 | 先明确领域正确性与展示边界，交付可验证结果 | 实验/复现/资料成本；不把演示当科学正确或市场验证 |
| 公开开源项目 | 用户愿公开可公开部分，有可复用能力、维护意愿及潜在受众 | 确认公开范围，准备最小可复现用法，再验证外部使用需求 | 文档、反馈、支持和维护；不因没钱就强推公开、不把star当收益 |
| 服务/定制/合作交付 | 有具体使用方/场景，适合先验证交付与付费意愿，尚不值得标准化产品 | 小范围试点，明确交付物、费用假设、双方职责和验收 | 人工交付/支持可能占时间；有重复需求和可持续交付证据再产品化 |
| 可重复收费产品（插件/软件/托管服务等） | 收入目标明确，有需求/付费证据或可验证试点，能承担持续开发、运营与支持 | 先验证核心价值、获客/交付及成本，再按证据扩展 | 持续服务/渠道/支持成本；资金多仍不跳过需求验证 |
| 接入既有产品/合作授权 | 用户有可交付能力或成果，合作方/现有平台能补渠道、工程或运营缺口 | 核对真实合作可能、交付边界、资源分工和收益假设 | 集成、协调与依赖成本；无合作证据时只列候选，不假称有渠道 |
| 暂缓或停止 | 当前可用路线均无法满足核心要求或投入边界 | 明确缺什么、达到什么条件才重评，保留可复用成果 | 不为给出“落地路线”而强行立项；未知需求与有证据否定分开 |

路线只比较有现实意义的候选，不要求每次填满此表。用户明确不愿公开或不想经营时，尊重其选择，不用资金档位替用户改目标。

## 4. 形成可执行建议

简单任务一段话即可；复杂任务写入decision，verdict引用其结论。至少说明：

1. **现在走哪条**：推荐交付途径与实现来源，为什么匹配当前目标/资源；关键备选为何暂不选。
2. **投多少、缺什么**：首期与持续现金、本人/团队时间、关键资源缺口。适用时计入维护、算力/API、支持和推广；已有资源与新增成本分开，估计附依据或区间。具体价格/服务条件在实际选型时核对官方当前资料，不写通用金额阈值。
3. **下一步验证**：最小产物、成功/失败判据、投入上限和停止/切换条件；无证据不编收入、回本期或省钱比例。
4. **若补齐资源**：有关键缺口或预算未知时，分别说明当前能做的轻量路径，以及获得时间/资金/技能/渠道后才适合的路径。先完成不依赖未知信息的调查；需要关键意图时只等待相应分支。

推荐开源、合作或商业路线不是发布、联系他人、付款、安装、成立项目或外发资料的授权。继续遵守SKILL中的保密与执行边界；本指引不改变两轴评分，也不自动重评旧idea或增加新的评分器。
